# tenkenkun_footway

これは、 OpenStreetMap の 歩道・小道・自転車道・階段（`highway=footway` / `path` / `cycleway` / `steps`）を 都道府県ごと に抽出し、QGIS で開ける GeoPackage（.gpkg） にして表示し **OpenStreetMapの歩道編集を補助する Google Colab ノートブック** です。
あわせて、確認したほうがよい場所を **確認候補レイヤ** として出力できます。

## 使い方

1. 下のボタンから Google Colab でノートブックを開きます。

   [![Open In Colab](https://colab.research.google.com/assets/colab-badge.svg)](https://colab.research.google.com/github/zunyu-osm/tenkenkun_footway/blob/main/tenkenkun_footway.ipynb)

2. コードのセルの **▶（実行）** を押します。
3. 都道府県の一覧が出るので、**番号（1〜47）を1つだけ** 入力します。複数指定や範囲外の番号は受け付けません。
4. 「品質チェックを実施しますか？」に `y`（する）か `n`（しない）を入力します。
5. 終わると .zipファイル が自動でダウンロードされます。展開して、`.gpkgファイル` を QGIS にドラッグ＆ドロップします。

初回は、データのダウンロードと読み込みで **数分〜十数分** かかることがあります。

## 出力ファイル（例：宮城県）

ZIP の名前は `QGIS表示用のレイヤーファイル_宮城県の歩道.zip` となります。

| ファイル | QGIS のレイヤ名 | 内容 |
|---|---|---|
| `宮城県の歩道.gpkg` | `宮城県_歩道` | 県内に存在している歩道・小道・自転車道・階段を線とする |
| `宮城県_QC1_未接続候補.gpkg` | `宮城県_QC1_未接続候補` | 端点がどの way ともノードを共有しておらず、3m 以内に別の way がある場所 |
| `宮城県_QC2_孤立ネットワーク.gpkg` | `宮城県_QC2_孤立ネットワーク` | 道路などとノードを共有せず、歩道系だけでつながっている塊 |
| `宮城県_QC3_歩道の重複候補.gpkg` | `宮城県_QC3_歩道の重複候補` | 同じ種類（同じ `highway`）で、ほぼ同じ位置に重なっている線 |
| `宮城県_QC4_横断道路タグ不足候補.gpkg` | `宮城県_QC4_横断道路タグ不足候補` | 歩道が道路を横断しているのにも関わらず、接続や横断タグが見当たらない場所 |
| `宮城県_QC5_タグ付け不足候補.gpkg` | `宮城県_QC5_タグ付け不足候補` | 表面の素材タグが足りない歩道 |

QC1〜QC5 は、品質チェックを「する」を選んだときだけ出力されます。該当が 0 件のチェックは、ファイルを作りません。

## 品質チェックの内容

結果は 「確認してほしい候補」 です。見つかった場所がすべて間違いとは限りません。航空写真や現地の情報を見て、直すかどうかを判断してください。

### QC1 未接続候補: 
歩道の端が、近くにある別の道とつながっていない場所です（端から3m以内に別の道がある場合だけ）。駐車場・公園・敷地・建物の出入り口でわざと終わっている歩道も入ります。
### QC2 孤立ネットワーク:
歩道どうしはつながっているものの、ほかの道路にまったくつながっていない歩道のかたまりです。本当に孤立している場合と、まわりの道路データがまだ入力されていない場合があります。
### QC3 歩道の重複候補:
ほぼ同じ場所に、同じ種類の歩道が二重に描かれている場所です（0.5m以内で、短いほうの80%以上が重なるもの）。歩道と自転車道のように種類が違うものは対象外です。
### QC4 横断歩道タグ不足候補:
道路を渡る歩道や横断歩道で、道路とのつなぎ方やタグ（OSMの属性）に足りないところがある場所です。レイヤは1つ（点）で、何が足りないかは issue 列で区別します。
### QC5 タグ付け不足候補:
路面の種類（surface）が入っていない歩道です。missing_tags 列に surface と入ります。件数がとても多くなることがあります。

#### QC4 の issue（タグ不足の種類）
| issue | 状態 |
|---|---|
|ノード未共有	|歩道と道路が重なっているのに、つなぐ点（ノード）に横断歩道がない。|
|横断歩道ノードなし	|歩道と道路は点（ノード）でつながっているが、その点に highway=crossing が付いていない。|
|横断歩道ノードの種類なし	|その点に highway=crossing はありますが、どんな横断歩道かを表す crossing=* が付いていません。値の例: 信号なしマークあり uncontrolled / 信号ありマークあり traffic_signals / マークなし unmarked など|
|横断歩道wayの種類なし	|道路との交点が見つからない。 footway=crossing の歩道で、 crossing=* が付いていません。|

正しい状態の例は、歩道と道路が同じ点（ノード）でつながっていて、その点に highway=crossing と crossing=uncontrolled などが付いている形です。

#### QC4 のレイヤに入っている主な列:

- contact … 道路との位置関係（交差 / 端点接触 / 交点なし）。端点接触は、歩道の端が道路にちょうど触れている状態（T字）です。
- road_osm_id, road_highway … 相手の道路
- footway, crossing … 歩道に付いているタグ
- way_is_crossing … 歩道に横断のタグ（footway=crossing など）が付いているか

#### 調べ方のルール:

- 対象にする道路は、service を除く主な道路です。service は駐車場の出入口などが多く、誤検出が増えるためです。
- 歩道の端が道路に触れているだけの場所（T字）は、footway=crossing などが付いた横断歩道だけを調べます。普通の歩道が道路の端につながっているだけの場所-は、問題なしとして扱います。
- 橋・トンネル、layer が違うもの（立体交差）は調べません。
- 道路が交点で2本に分かれている場合など、同じ交点は1件だけ出します。
- 横断歩道の点（ノード）を読み込めなかったときは、「ノード未共有」だけを調べます

## 設定の変更

コードのセルの先頭近くにある設定を変えると、判定が変わります。

| 設定 | 初期値 | 意味 |
|---|---|---|
| `NEAR_TOL` | 3.0 | 未接続候補を探す距離（m） |
| `DUP_TOL` / `DUP_OVERLAP` | 0.5 / 0.80 | 重複とみなす距離（m）と重なりの割合 |
| `ROAD_HIGHWAYS` | service を除く | 横断を調べる相手の道路の種類 |
| `PBF_MAX_AGE_HOURS` | 24 | 取得済みデータを再利用する時間（これより古いと再取得） |

## 動作の仕組み

- 表示したい都道府県を選んでもらい、 Geofabrik の地方別ファイル（北海道、東北、関東、中部、関西、中国、四国、九州）を取得します。
- 県の範囲だけを `osmium extract` で切り出してから読み込みます。osmium-tool は自動でインストールします。失敗したときは、地方全体のファイルから読みます。
- 都道府県の境界は、[dataofjapan/land](https://github.com/dataofjapan/land) の簡易ポリゴンを使います。取得できないとき、品質チェックは中止します。チェックなしの場合は、警告を出して bbox で代用します。
- 距離の計算は、県の経度から選んだ UTM 座標系（メートル）で行います。

## QGISでのOpenStreetMapの表示の仕方
- 表示がない場合、追加できます。メニュー左側のブラウザのXYZタイルを右クリックして、表示されたXYZ接続タブの名前のところを OpenStreetMap にし、URLをhttps://tile.openstreetmap.org/{z}/{x}/{y}.png と入力してOKと押します。レイヤで一番下にします。

## 注意

- 大きい県（北海道など）は、無料版 Colab ではメモリ不足で止まることがあります。
- 全国の一括処理はできません。県ごとに実行してください。
- 簡易ポリゴンのため、県境の近くでは、隣の県の way が少し混ざることがあります。
- 品質チェックで表示される場所すべてが誤りではありません、 **確認してほしい候補** です。
